# Deploying the KinLAN API (Render + Neon)

The API runs as one free web service on **Render** (Singapore), backed by a free **Neon** PostgreSQL database (AWS Singapore). `render.yaml` at the repository root describes the service, so Render can create it as a Blueprint. Secrets never go in the repository.

| Piece | Where | Notes |
|---|---|---|
| API | Render web service `kinlan-api`, free plan | `https://kinlan-api.onrender.com` if the name is free (Render adds a suffix otherwise) |
| Database | Neon project `kinlan`, branch `main`, database `kinlan` | Pooled string for the app, direct string for migrations |
| Migrations | `alembic upgrade head` in the start command | Free instances have no pre-deploy step |
| Scheduled jobs | Inside the same process (APScheduler) | Keep **one** instance; set `RUN_JOBS=false` on any extra one |
| Deploys | Automatic on `main`, only after CI passes | `autoDeployTrigger: checksPass` |

## 1. Create the Neon database (once)

1. Sign in at <https://console.neon.tech> and choose **New project**.
   - Name: `kinlan`
   - Postgres version: 17
   - Region: **AWS Asia Pacific (Singapore)**, the closest to the Philippines
   - Database name: `kinlan`
2. Open **Connect** on the project dashboard and copy two connection strings for branch `main`:
   - **Pooled** (the host contains `-pooler`): this becomes `DATABASE_URL`.
   - **Direct** (turn connection pooling off): this becomes `DATABASE_URL_UNPOOLED`.
3. Paste them exactly as shown (`postgresql://…?sslmode=require&channel_binding=require`). The server adds the `postgresql+psycopg://` driver prefix itself.

Why two strings: Neon's pooler is PgBouncer in transaction mode. It suits the app's short queries, but migrations need a real session, so Alembic uses the direct string.

## 2. Create the Render service (once)

1. Sign in at <https://dashboard.render.com> with GitHub and allow access to `KirkGamo/kinlan`.
2. Choose **New → Blueprint**, pick the `kinlan` repository and branch `main`. Render reads `render.yaml`.
3. When it asks for the variables marked `sync: false`, paste:
   - `DATABASE_URL`: the Neon **pooled** string
   - `DATABASE_URL_UNPOOLED`: the Neon **direct** string
4. Apply. The first deploy installs the requirements, runs `alembic upgrade head` (creating every table), then starts Uvicorn. `JWT_SECRET` is generated by Render.

## 3. Check it

```bash
curl https://kinlan-api.onrender.com/healthz
```

It should answer `{"status":"ok","version":"0.1.0"}`. The interactive API reference is at `/docs` (screenshot it for the progress report). The Render log should show `scheduler started: check_heartbeats, rollup_hourly, retention`.

## 4. Point an agent at it

On the monitored PC (in an elevated prompt):

```bash
kinlan-agent pair --api-url https://kinlan-api.onrender.com
kinlan-agent run
```

Make the pairing code in the app, or for now with the API: register, create a Circle and a site, then `POST /api/v1/sites/{site}/pairing-code`.

## Free-tier behaviour to know

- **Render free instances sleep** after 15 minutes without requests, and the next request waits about a minute while one wakes it. A running agent uploads every 30 seconds, so a monitored deployment stays awake. One always-on service uses about 744 of the 750 free instance-hours a month.
- **Neon free computes suspend** after 5 idle minutes. The first query after that takes a few hundred milliseconds longer. Storage is 0.5 GB; the plan's estimate for 3 sites with 7 days of raw samples is 40–60 MB.
- **Restarts lose nothing:** the agent buffers while the API is down or waking, then uploads oldest first.

## Rolling back

- **Code:** in Render, **Events → a previous deploy → Rollback**, or revert the commit on `main`.
- **Data:** Neon can restore a branch to an earlier point in time (**Branches → Restore**). Take a manual `pg_dump` with the direct string before the progress report, the submission and the defense (Section 5.3 of the plan); store dumps in `docs/backups/`, which is git-ignored.
- **A bad migration:** test it first on a Neon branch of `main` (**Branches → New branch**), using that branch's direct string with `alembic upgrade head`.
